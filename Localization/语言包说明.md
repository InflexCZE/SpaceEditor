# 语言包说明

`Strings.en.xaml` 保存程序默认英文文案。`zh-CN.json` 保存简体中文翻译，由程序在选择简体中文时加载。

## 只更新中文补丁

将新的 `zh-CN.json` 放到可执行文件旁的 `Localization` 文件夹，覆盖旧的同名文件。重启程序，或在界面中先切换到英文，再切换到简体中文，便会重新读取语言包。

外部 JSON 语言包优先于随程序集附带的中文翻译。外部文件缺失、无法读取或 JSON 无效时，使用内置中文翻译。外部文件中的某项文案缺失时，使用默认英文资源。

该方式需要原作者先合并语言加载代码；语言包不能直接汉化尚未包含该入口的旧版 EXE。

## 文件结构

```json
{
  "strings": {
    "MainWindow_Main": "主页",
    "ModelName": "模型：{0}"
  },
  "names": {
    "SlopesUpper": "生成顶部斜坡",
    "Mouse": "鼠标"
  }
}
```

- `strings`：固定界面文字、提示、文件对话框标题等。键名对应英文资源，保持稳定。
- `names`：模型属性、按键及游戏控制器的显示名称。支持完整名称匹配和已有英文词条组合，匹配时忽略大小写；未知名称保留原文。
- `{0}`、`{1:f2}` 等格式占位符必须保留，允许按中文语序调整位置。
- JSON 使用 UTF-8 编码，不添加注释。
- 程序只将 JSON 作为字符串数据读取，不执行语言包代码或改变进程的区域设置。

## 作者新增英文功能时

将新的英文文案加入 `Strings.en.xaml`，在 XAML 中用 `DynamicResource` 引用，或在 C# 中调用 `LocalizationManager.Text`。在中文包中补充对应键即可，无需改动其他功能代码。

若未补充中文，新的资源会显示英文；若文案仍直接写在功能代码中，则语言包无法覆盖。游戏程序集升级引入的新名称也可能暂时显示原文。

## 数据边界

语言切换不会翻译游戏 GUID、输入 ID、程序集名、反射查找参数、属性绑定路径或配置键。自定义预设和蓝图名称保持用户输入。方块尺寸的中文显示也不会改写生成算法使用的原值。

系统对话框通用按钮由 Windows 语言决定，RGB、HSV 等标准缩写及外部异常堆栈可能保留英文。
